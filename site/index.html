What makes it different

Recommendations that stay on your machine.

No cloud inference, no account, no library scan. The parts that can touch the network are optional and only run when you ask.

Local-first core

Prompt → intent → playlist runs entirely offline. A local llama.cpp model, or a built-in rules parser if you skip the model, plus a vector walk over a catalog on your disk.

The model never picks songs

Its whole job is text → a small structured intent. It never sees the catalog and never ranks tracks. Selection is deterministic Go — same prompt and seed, same playlist.

Then it leaves

When you're happy, resolve ISRCs via MusicBrainz and hand off to Soundiiz — a tokenless browser handoff — or export a CSV you import yourself.

How it works

Four steps, and only the last one is online.

01

Prompt

Name a seed artist and describe the rest in plain language. A live preview shows the parse as you type.

02

Intent

The parser emits MusicIntent: seeds, count, mode, and the creativity / noise / lookback knobs — nothing else.

03

Vector walk

Resolve seeds against the catalog, then step outward by blended-cosine nearest-neighbour, with a dash of Gaussian noise and artist de-duping.

04

Export

Optionally enrich with MusicBrainz, then Soundiiz handoff or CSV. This is the only step that needs the network.

Invariant: prompt → playlist is 100% local. The LLM only does text → intent; every track choice is made by deterministic code you can read.
Details

Everything you'd want in the box.

Built on the Deej-AI embedding technique, wrapped in a native desktop app.

~957k-track catalog

Derived from the Deej-AI dataset. A ~210 MB compressed archive the app downloads once and decompresses into your data dir. Not in the repo, not in the installer.

Two spaces, one slider

Every track has a playlist-co-occurrence embedding and an audio-content embedding. Creativity blends them; Noise makes the walk wander.

Similar & journey modes

One seed walks outward from that sound. Two or more seeds interpolate a path between them — a gradual crossfade across the catalog.

Instant, reproducible

Move a slider and the walk re-runs immediately — no re-parse. A pinned seed makes any playlist replayable, and “Regenerate” rolls a fresh one.

Local LLM, optional

On first run the wizard installs llama.cpp — a GPU build (CUDA / ROCm / Vulkan / Metal) plus a CPU fallback. Pick a curated GGUF or bring your own. No model? The rules parser still works.

Soundiiz & CSV export

A tokenless Soundiiz browser handoff writes straight to your streaming service, or download a Soundiiz-compatible CSV. ISRCs resolved via MusicBrainz first.

30-second previews

Deezer's public preview API, with a bundled Spotify-CDN fallback, and a mini player — no API key. Or turn playback off entirely.

Local playlist history

Every generation is saved to a local SQLite file with a short auto-title, and any past prompt can seed a new one.

Surprise me

One click generates from a random curated prompt — a fast way to explore the catalog without typing.

Privacy

What stays, and what leaves.

No accounts, no telemetry, no cloud inference. Every network call is optional and started by you.

Stays on your machine

  • Your prompts and parsed intents
  • The model, and all inference
  • The recommendation catalog and the walk
  • Playlist history (a local SQLite file)
  • Preferences and the MusicBrainz cache

Leaves only when you act

  • First launch: downloads the catalog archive and the llama.cpp installer
  • Enrichment: track + artist names to MusicBrainz for ISRCs
  • Soundiiz handoff: playlist title and track/artist names
  • Previews: a track lookup to Deezer's public API

For developers

Build it from source.

No Git LFS, no large blobs. The Go core tests need only Go; the desktop app needs the Wails v3 CLI.

# Go core — no toolchain beyond Go
go test ./...

# Full desktop app
go install github.com/wailsapp/wails/v3/cmd/wails3@v3.0.0-beta.16
wails3 doctor      # check system deps
wails3 dev         # hot-reload run
wails3 build       # bin/playlist-ai
wails3 package     # per-OS installers

Architecture, the catalog pipeline, and the release process are documented in ARCHITECTURE.md, CATALOG.md, and RELEASING.md.
