02 / THE LATEST PRESSING

Better filtering.
A clearer next listen.

Version 0.11.0 is out now. Recommendations start with a wider shortlist, playlist messages explain what was actually fulfilled, and new log controls help you understand the result. Upgrade without resetting your history or installed models.

Read the 0.11.0 release notes ↗
01

A wider shortlist, checked down

Evidence-aware recommendations aim for twice the requested count before AcousticBrainz and CLAP checks. Bounded refill preserves exclusions, recording deduplication and journey order. A full playlist still depends on eligible tracks and available evidence.

02

Playlist messages that add up

A full-length result no longer always says “verified partial playlist.” Shortfalls show the returned and requested counts; unverified musical details keep their explanations. Reaching ten tracks does not prove every request detail was met.

03

Useful logs, under your control

Select DEBUG, INFO, WARN or ERROR in the log window. Detailed diagnostics are opt-in and memory-only; selecting a higher level stops and clears DEBUG collection. Review private prompts and listening details before sharing logs.

04

Small details, easier listening

A clearer Generate layout, keyboard-accessible track details, improved light/dark contrast and computer, sun and moon theme icons. Linux ARM64 packaging now carries the correct target architecture.

Every nonempty playlist contained ten tracks and met its artist-variety requirement. There were no recording-duplicate or back-to-back artist failures. The single-artist request is exempt from artist spacing.

A full list isn’t the same as a fulfilled request.

Each enhanced mode reported 12 fulfilled playlists, 27 partial results and one request needing clarification. Deej-AI-only reported nine fulfilled, 26 needing clarification and five unsupported. No mode met the five-track target for every prompt.

What still needs work.

Both enhanced modes placed “sparkle” in the wrong intent field and returned no tracks for the David Bowie → Talking Heads journey. Engine-only lacked usable seeds or support for many richer requests. These failures remain in the report.

Timing, evidence coverage & test conditions

Median per-request time: 42.3 s for AcousticBrainz-first, 28.3 s for CLAP-first and 0.584 s for Deej-AI-only. The slowest strict instrumental request took 11.8 minutes in the first run.

This is not a controlled speed comparison. The first mode parsed fresh; the others reused those interpretations, and CLAP-first benefited from warmer caches. Engine-only skipped auxiliary services and could not fulfill most requests. Startup is excluded.

Each enhanced run had analyzed preview evidence for 270 of 390 selected tracks, but no selected-track AcousticBrainz comparison scores. Some archive data was available for candidates. Coverage was insufficient to establish which source priority sounds better.

Test host: RTX 5060 Laptop GPU with 8 GB VRAM, Linux/WSL2, local Qwen3.5-9B, CPU CLAP, a 956,917-track catalog and an empty taste profile. No held-out listening judgments were used. The full repository check gate passed separately from these live acceptance failures.

Full results & reproduction steps ↗

Less repeated work. Same exact neighbors.

A request-local search cache reduced a reference-based, ten-track benchmark from 1.888 s to 0.325 s—about 5.8× faster, with identical playlists and scoring evidence. This isolates recommendation work: model parsing, provider calls and CLAP are excluded. It is not a whole-app speedup claim.

A FEW GOOD QUESTIONS

Before you
press play.

Do I need a language model?

It’s optional. A local language model helps interpret richer descriptions and infer starting points. Without one, basic interpretation is available; supported discovery still depends on your mode and available evidence. Deej-AI-only requires a resolved catalog artist or track. Naming a reference can help when a description cannot be fulfilled.

Is Deej-AI-only the same as turning off the LLM?

No. The language model interprets your words; the recommendation mode decides how tracks are retrieved and ranked. Deej-AI-only can still use a local LLM to interpret a named reference, but it does not verify musical characteristics with CLAP or AcousticBrainz.

Does everything work offline?

Language inference, recommendation processing, history and taste profiles stay local. Setup needs downloads, and metadata discovery, preview lookups and Soundiiz handoff use external services. CSV export uses local track details.

Can I use my own CLAP model?

Yes, with compatible paired encoders, tokenizer, preprocessing and reference checks. Different checkpoints keep separate embedding caches. Read the custom-bundle guide for the contract and links to training and export documentation.

Does CLAP work on every build?

Native inference was validated on Linux x64 under WSL2 and on Windows x64 through the documented development checks. Current native-enabled builds include the worker; setup downloads its compatible model and runtime. Older pure-Go builds may need an upgrade. Windows ARM64 inference, clean Windows runtime prerequisites and hardened macOS signing still need validation. See the build-specific evidence and limitations before installing analysis models.

How do I upgrade to 0.11.0?

Install the matching package from the latest release, or use the update prompt in supported installations. No data reset is required: existing history, settings, catalogs and installed models remain compatible. Regeneration can change results because the recommendation strategy has changed. Complete installed-updater flows have not been verified on every platform.

What was tested for this release?

Hosted CI and packaging passed for all release targets, and all 17 asset checksums were verified. The frontend has 35 passing behavioral tests. Coverage remains incomplete: 78.52% backend statements and 6.81% frontend lines, not the requested 95% target. These checks are not proof of musical quality; no new held-out listening study was run for 0.11.0. See the coverage report and remaining gaps.

How can I see why a track was chosen?

Open Settings → Application logs → Open logs and choose DEBUG. Available interpretation and analysis evidence appears in memory-only diagnostics. Selecting INFO, WARN or ERROR stops and clears DEBUG collection. Detailed logs may include private prompts and listening data; review them before sharing. Read the logging and privacy guide.

Why might I get fewer tracks than requested?

Not every description or recording has enough supporting evidence. Playlist AI explains partial results rather than filling the list with tracks that fail essential requirements. You can refine your description or choose another reference.

Can I build it myself?

Absolutely. Playlist AI is GPL-3.0 software built with Go, Wails and React. The repository setup instructions cover the desktop toolchain. Python is not a desktop runtime requirement.
