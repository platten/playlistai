What makes it different

Recommendations that stay on your machine.

No cloud inference, no account, no library scan. The parts that can touch the network are optional and only run when you ask.

Local-first core

Prompt → intent → playlist runs locally. The desktop core is compiled Go; an optional llama.cpp model parses language, and the built-in rules mode works without it.

The model never picks songs

Its whole job is text → structured musical intent. It never sees the catalog or ranks tracks. Every pick comes from transparent retrieval, eligibility, ranking, and sequencing code.

Your feedback stays yours

Likes, dislikes, request-only feedback, exposures, taste clusters, and history live in local SQLite. Generated or briefly previewed tracks are never silently treated as feedback.

How it works

From musical meaning to an ordered playlist.

Each boundary has one job, so hard rules cannot be blurred into preferences and every selected track can carry real scoring evidence.

01

Interpret

Preserve references, required tracks, mood, texture, exclusions, count, journey, and source evidence in a versioned intent.

02

Resolve

Match artists and tracks separately, Unicode intact. Exact matches win; material ambiguity is shown instead of guessed away.

03

Retrieve & rank

Search each reference in both embedding spaces, add taste clusters and bounded exploration, then score transparent components.

04

Select & order

Apply hard exclusions and recording dedup, select diverse relevant tracks with MMR, then optimize transitions and waypoints.

05

Export

Preview, enrich with MusicBrainz, or use Soundiiz. CSV stays local; every network action is optional and explicit.

Invariant: the LLM only does text → intent. Hard exclusions run before ranking, exposures are not likes, and the same catalog, algorithm, intent, profile snapshot, and seed reproduce the same result.
Details

More control, without pretending to know more.

The pipeline uses only available evidence, reports missing capabilities, and keeps the original Deej-AI walk as a versioned evaluation baseline.

~957k-track catalog

Derived from the Deej-AI dataset. A ~210 MB compressed archive the app downloads once and decompresses into your data dir. Not in the repo, not in the installer.

Multi-channel retrieval

Each reference independently searches audio and playlist-co-occurrence space. Taste clusters and bounded exploration contribute separate candidates with provenance.

Similar & journey modes

One or many references can anchor a playlist. Required tracks stay distinct, waypoint order is preserved, and the requested count always means total output tracks.

Responsive & reproducible

Initial results are reused, stale work is cancelled, and sliders retain the full intent. Catalog, algorithm, profile snapshot, context, and a lossless seed identify each build.

Hardware-aware local models

The wizard asks llama.cpp for usable GPUs and free VRAM, reserves 1 GiB for context/KV, and lists only complete weights that fit. CPU mode shows the two smallest choices.

Explicit local feedback

Like, dislike, more-like, less-like, acceptance, and removal are explicit events. Recency-weighted positive and negative clusters preserve multiple tastes.

Hard rules stay hard

Artist/track exclusions and recording duplicates are eligibility rules, never soft penalties. Exhaustion returns a visible partial-result reason instead of an ineligible fallback.

Grounded semantics, optional

A versioned sidecar can add reviewed descriptions and facets. Missing evidence stays unknown; unsupported phrases remain in the intent instead of becoming fabricated metadata.

History & continuing radio

History stores the complete result for exact replay. Continuing radio retains the original anchor while incorporating recent selections and relevant taste clusters.

Soundiiz & CSV export

Resolve ISRCs through cached, rate-limited MusicBrainz enrichment, use a tokenless Soundiiz browser handoff, or download a compatible CSV.

Optional 30-second previews

Use Deezer's public preview lookup, the URL already stored in the catalog, or turn playback off. Preview behavior never becomes implicit taste feedback.

Evaluation built in

A repeatable harness measures intent, resolution, retrieval, ranking, hard violations, diversity, transitions, reproducibility, and stage latency without calling synthetic data musical proof.

Hardware-aware model setup

The wizard keeps this priority order, then filters it using free memory reported by the installed llama.cpp backend. A full GGUF must fit on one GPU with 1 GiB still available for context, KV cache, and compute.

  1. Qwen3.5 35B A3B
  2. Qwen3.5 9B
  3. Mistral Small 3.1 24B
  4. Gemma 3 12B
  5. Qwen3.5 4B

Measured example: the test RTX 5060 Laptop GPU reports 8123 MiB total and 7033 MiB free through llama.cpp, so Qwen3.5 9B and 4B fit with the reserve. Capacity tests extend through 24 and 32 GiB reference profiles for RTX 5090-class hardware; all five curated weights fit those profiles. Real choices always use currently free memory. If no usable GPU backend is reported, the two smallest recommended models are offered for CPU use.

Privacy

What stays, and what leaves.

No accounts, no telemetry, no cloud inference. Every network call is optional and started by you.

Stays on your machine

  • Your prompts and parsed intents
  • The optional model, and all intent inference
  • Retrieval, ranking, selection, and sequencing
  • Playlist history, explicit feedback, and taste profiles
  • Preferences, exposures, and the MusicBrainz cache

Leaves only when you act

  • Setup: downloads the catalog; llama.cpp and a model only if you choose them
  • Enrichment: track + artist names to MusicBrainz for ISRCs
  • Soundiiz handoff: playlist title and track/artist names
  • Previews: a track lookup to Deezer's public API

For developers

Build it from source.

No Git LFS, no large blobs, and no Python runtime. The compiled Go core tests need only Go; the desktop shell needs the Wails v3 CLI.

# Go core — no toolchain beyond Go
go test ./...

# Full desktop app
go install github.com/wailsapp/wails/v3/cmd/wails3@v3.0.0-beta.16
wails3 doctor      # check system deps
wails3 dev         # hot-reload run
wails3 build       # bin/playlist-ai
wails3 package     # per-OS installers

Architecture, catalog, and evaluation details are documented in ARCHITECTURE.md, CATALOG.md, and EVALUATION.md.
