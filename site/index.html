A FEW GOOD QUESTIONS

Before you
press play.

Do I need a language model?

It’s optional. A local language model helps interpret richer descriptions and infer starting points. Without one, Generate works with the local catalog and asks for a seed artist or track.

Does everything work offline?

Language inference, recommendation processing, history and taste profiles stay local. Setup needs downloads, and metadata discovery, preview lookups and Soundiiz handoff use external services. CSV export uses local track details.

Can I use my own CLAP model?

Yes, with compatible paired encoders, tokenizer, preprocessing and reference checks. Different checkpoints keep separate embedding caches. Read the custom-bundle guide for the contract and links to training and export documentation.

Does CLAP work on every build?

Native inference was validated on Linux x64 under WSL2. The standard pure-Go Windows build needs a native-enabled build or a legacy bundle with its own worker. Hardened macOS builds still need a signing strategy for downloaded runtimes. See the documented limitations before installing analysis models.

Why might I get fewer tracks than requested?

Not every description or recording has enough supporting evidence. Playlist AI explains partial results rather than filling the list with tracks that fail essential requirements. You can refine your description or choose another reference.

Can I build it myself?

Absolutely. Playlist AI is GPL-3.0 software built with Go, Wails and React. The repository setup instructions cover the desktop toolchain. Python is not a desktop runtime requirement.
