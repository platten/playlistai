# Enhanced Hybrid provider and translation contract audit

Investigated 2026-09-12 against `7e91fc199c57b1487aa315f6a9c382db2c4364e8` on `codex/enhanced-audio-remaining`. This is a research artifact, not an implementation or a musical-quality claim. Repository code and existing measurements were inspected; provider documentation was read without requesting user recordings, downloading datasets or running live recommendation jobs in this subtask.

## Findings that change the remediation plan

1. **There is no common classifier vocabulary to send to these four systems.** CLAP accepts music descriptions and audio in a paired embedding space. MERT accepts audio only. MusicBrainz accepts identity/tag searches and returns contributed metadata. AcousticBrainz accepts recording MBIDs and returns archived measurements/class predictions. A dictionary should compile one preserved user intent into four different query/evidence contracts.
2. **Enhanced currently inherits AcousticBrainz-first ranking.** In `internal/reco/multichannel/ranker.go:44`, only CLAP-first gets CLAP precedence; Enhanced enters `preferAcousticRanking`. The archive weight is `.55` (`acoustic.go:17`), versus the default semantic weight `.35` (`config.go:57`). A decisive archive prediction removes the overlapping CLAP ranking contribution (`acoustic.go:217`). These are engineering policies, not weights calibrated on listener judgments. Enhanced adds MERT and DSP later, each bounded to `.15` (`enhanced.go:117`), and cannot use those additions to recover candidates already excluded.
3. **Orthographic aliases and taxonomy relations are conflated inconsistently.** `NormalizeIdentityPart` only lowercases and collapses whitespace (`internal/core/track.go:33`). AcousticBrainz calls it directly, while other semantic paths use `CanonicalStyle` (`internal/core/semantic_evidence.go:24`). Consequently the spelling variant `hip-hop` does not hit AcousticBrainz's `hip hop` entry. Separately, the core collapses `electronica` to `electronic`, whereas AcousticBrainz does not. That difference is confirmed code behavior, but existing code does not establish that the two concepts are synonyms: electronica may be narrower than a source's broad electronic class. Review that relation rather than propagating an unproven equivalence.
4. **Provider evidence is available but unmapped.** The application retains high-level `danceability`, `timbre` and `tonal_atonal`, but `acousticClass` has no mappings for them. It retains BPM, key, danceability and dynamics measurements, but searches of production Go show these low-level values are stored rather than used for intent scoring. Several broad genre classes are also deliberately omitted because their meanings are composite or conditional.
5. **The current raw-prompt rescue happens too late and is too narrow.** `enhanced_phrases.go:19` recognizes a small vocabulary only inside Enhanced DSP ranking. It neither repairs the saved intent nor informs CLAP or metadata discovery. It skips raw extraction entirely for journeys/scoped clauses, and relies on already resolved references when masking names.
6. **A dictionary cannot compensate for an unhealthy embedding space or absent audio.** Existing music-only CLAP smoke results show nearly identical unrelated text embeddings (`docs/clap-model-candidates.md:39`). Reproduce that anomaly in the upstream model and native export before tuning text templates or score thresholds. Cached CLAP retrieval scans compatible analyses only (`internal/audio/cached_search.go:57`); it cannot discover unheard catalog tracks by text without candidate acquisition.

The latter explicitly describes `genre_electronic` as a within-electronic classifier. Its historical evaluation figures measure their own datasets, not this catalog or Deezer previews.

Current scoring uses requested-class probability minus the strongest competing class, flips it for negative clauses, and averages applicable models. Margins at least `.5` support a clause; margins at most `-.5` oppose it. Contradictory models remain conflicting. Positive archive evidence does not itself satisfy strict eligibility, while strong opposition can block essential/strict clauses (`internal/reco/multichannel/acoustic.go:79`, `:169`). This creates asymmetric admission: archival disagreement can reduce count even when the user would accept a clearly labeled close match. Revisit the gating only for relaxable preferences under the user's chosen fallback policy.

Low-level descriptor semantics also need typed units. Essentia's `average_loudness` is a dynamic-range descriptor, with larger values representing less dynamic range; it is not the application's dBFS measure. Extractor/model versions must agree. [Essentia music extractor](https://essentia.upf.edu/streaming_extractor_music.html) The application's core type already identifies its low-level danceability scale as distinct from a 0–1 classifier score (`internal/core/acoustic.go:19`).

## CLAP and MERT limitations relevant to improved results

`audio.Clauses` reads essential criteria, semantic preferences and supported/unsupported hard constraints, falling back to the entire original description only if there are no structured clauses or references (`internal/audio/session.go:121`). Thus one extracted genre can prevent otherwise lost natural-language nuance from reaching CLAP at all. The present query ensemble emits the original clause plus one generic caption by facet (`internal/audio/query.go:18`). It introduces no synonyms, and strict clauses bypass the new caption ensemble. General similarity remains uncalibrated unless the selected bundle has a valid reviewed policy.

CLAP averages sampled-segment similarity for positives and uses the maximum for exclusions (`session.go:340`). Vocal absence uses a separate instrumental-versus-singing/speech/noise comparison on every sampled segment, including a `.02` engineering abstention band (`vocals.go:42`). Therefore treating “mostly instrumental” as “absolutely no vocals” can sharply reduce count. Preserve degree and explicitness before LLM interpretation.

MERT ranking currently takes resolved positive/negative reference representatives if compatible audio exists; the common reference path can also include permitted inferred anchors (`internal/reco/multichannel/vectors.go:46`). Otherwise it falls back to taste centroids (`enhanced.go:117`). A description-only request without usable audio references can obtain no text-specific MERT preference. The present code already averages similarity across several artist representatives rather than relying on a single named song. Evaluate whether the representatives cover the requested part of that artist's work: compare unsupervised medoids and representatives selected by the current CLAP/DSP request against the current weighted average. Do not assume artist names themselves are audible classifiers.

CLAP/DSP sample a centered interval of random duration, using all short previews and 22–47 seconds when available (`internal/audio/sampling.go:11`). MERT analyzes at most the first 30 available seconds. Exact analyzed bounds and hashes must therefore be recorded for reproducible ablations, and no source establishes unseen portions of a recording. Warm-cache and cold-preview runs are different experiments.

## Recommended dictionary contract

Store an embedded versioned concept registry in Go-readable JSON or generated tables. Python may help prepare and audit sources offline; loading and use must remain native on each desktop OS. The registry should contain concept ID, display name, exact aliases, source/licensing/version, typed facet, polarity/degree cues, parent/related concepts, provider mappings, mapping strength and counterexamples. Keep orthographic aliases, reviewed semantic synonyms, source-specific broader/narrower relations and retrieval-only related concepts as distinct relation types. A broad provider label cannot establish a narrower user concept. Separate artist aliases into the existing identity resolver rather than polluting the musical-concept dictionary.

Extract spans before the LLM, with longest exact phrase matching, punctuation/Unicode-aware normalization, bounded morphology and explicit negation scope. Keep the original character span and wording. Protect resolved/quoted artist and track names, stage boundaries, numbers, artist exclusions and explicit must/only constraints. Do not classify `Christian` as religious music inside a possible misspelled artist name. The user's `christrian loeffler` should be a resolver candidate for `Christian Löffler`, with a correction record and ambiguity handling, not an invented exact alias silently accepted everywhere.

Use two evidence classes:

- **Locked extraction:** unambiguous explicit user constraints, exact known genres and verified identity matches. These override conflicting LLM output, with a recorded conflict rather than a silent overwrite.
- **Interpretation proposals:** ambiguous mood, activity, sonic metaphors and related-genre expansion. These remain soft and can be refined by the LLM; they never become verified musical facts merely because the dictionary contains them.

Compile after deterministic reconciliation into provider-specific plans. All consumers should share concept IDs and canonicalization: discovery, metadata acceptance, CLAP caption generation, AcousticBrainz mapping, DSP preferences, selection and history replay. Preserve the original phrase alongside the normalized representation. Version the query plan/fingerprint separately from audio embeddings, so correcting aliases does not force audio reanalysis but does invalidate stale assessments/rankings.

## Prioritized remediation and acceptance criteria

1. **Model/query health gate.** Reproduce music-only text collapse against upstream pinned Python and native encoder using identical token IDs/masks, pooling and paired weights. Include related/unrelated captions and matched/mismatched music pairs. Validate tokenization, padding, truncation, model hashes, pair compatibility and score distributions. Numerical parity and text-text diversity are diagnostics; actual retrieval/listener measurements decide quality. Keep a healthy compatible checkpoint as a separately versioned comparison.
2. **Unify intent concepts before changing scores.** Replace scattered exact-string rules with the registry and protected span extraction/reconciliation. Reviewed orthographic alias tests must yield equivalent provider plans for hip hop/hip-hop and approved drum-and-bass spellings. Test electronica/electronic separately as a source-specific taxonomy question; do not assert synonymy merely because `CanonicalStyle` currently collapses them. Negation, ambiguity, degree, quoted names, journeys and historical replay must remain stable.
3. **Expand safe mappings.** Add timbre, tonal/atonal, danceability and explicit tempo contracts. Use conditional electronic subgenre scores only with independent evidence that electronic music is applicable; never map dubstep to dnb. Composite class support is broad evidence, not proof of any narrower member. Add parent mappings for retrieval only where verified directional relations exist.
4. **Improve Enhanced evidence combination.** Compare existing archive-first masking with per-facet evidence fusion and quality-weighted source reliability. Avoid summing correlated aliases/genre ancestors or double-counting the same DSP axis. Keep unsupported facets unknown and separate from known mismatch. Evaluate whether broad archive opposition should downgrade a relaxable preference rather than discard the candidate, while preserving explicit strict exclusions.
5. **Increase count by expanding evidence, then labeled fallback.** First retrieve additional exact aliases, cached CLAP candidates, reference neighborhoods and approved related genres. Prefer candidates whose useful evidence already exists; analyze new previews in a bounded, diversity-aware order. User preference is strong matches first, then clearly labeled close matches to reach count. Close matches must disclose which optional facets are unsupported or approximate; explicit hard exclusions and must/only clauses remain non-negotiable. All tiers retain recording deduplication and journey order.
6. **Evaluate MERT's real contribution.** For the user's artist-centric music interests, compare multiple actual reference medoids and last-layer pooling against a small fixed alternative layer/pooling study, without training a new supervised head. Record CPU latency, peak memory and available-reference count. Only ship a new space if it improves held-out retrieval/listening; old embeddings remain separately identified.

Ablate baseline, pre-LLM extraction only, provider canonicalization only, new CLAP queries, added numeric/DSP facets, source fusion, MERT reference selection and labeled fallback separately. Measure protected-span recall, spurious hard constraints, per-provider mapping coverage, preview acquisition success, candidates rejected per reason, requested-count fulfillment, strong/close tier counts, hard-exclusion violations, per-facet relevance and listener preference. Use the additional real-world prompt set from the coordinating investigation and keep prompt interpretation scores separate from musical quality.

## Distribution, licenses and remaining uncertainty

AcousticBrainz stopped collecting new submissions in 2022; its API currently exposes the archive. Its dataset is declared CC0. This is useful reusable evidence but cannot be assumed to cover newer recordings. [AcousticBrainz project status](https://acousticbrainz.org/)

MusicBrainz core data is CC0, while supplementary data uses CC-BY-NC-SA 3.0. Record actual source tables and attribution for any redistributed genre/tag dictionary instead of assuming every field shares the core license. [MusicBrainz data license](https://musicbrainz.org/doc/About/Data_License) MERT's existing noncommercial model restriction remains; a new dictionary does not remove it. Newer Essentia classifiers are separate model products, commonly CC-BY-NC-SA 4.0 or proprietary, not a free upgrade implied by access to the CC0 archive. [Essentia model inventory and licenses](https://essentia.upf.edu/models.html)

No new datasets or classifiers were downloaded in this research-only subtask. A derived concept dictionary and preprocessing tools do not require source music. Future musical validation still needs authorized source PCM or identity-matched Deezer previews, an explicit coverage manifest, and the user's retained source downloads in `C:\Users\pawel\Downloads` when datasets are actually obtained.

Unresolved measurements: actual installed checkpoint behavior on the new prompt set; compatible cached-audio breadth; archive coverage and disagreement on the user's genres; hearing-based relevance of the proposed mappings; whether MERT improves artist-level matching enough to justify latency. These require the coordinating tests and later controlled implementation/evaluation, not conclusions from API documentation.
