# Ten-prompt semantic translation audit

Reviewed 2026-09-12. Inputs: `docs/data/enhanced-translation-prompts-v1.json`; two existing native parser reports, `bin/enhanced-translation-investigation/native-parser/ai-parser-1.json` and `ai-parser-2.json`. The latter are ignored local investigation artifacts. Parser reports identify `llama/v13`, contract 8 and catalog `1:956917:1788613313`. The reports are parse-only and name the default AcousticBrainz-first mode; this audit evaluates the shared intent contract that Enhanced subsequently consumes, not Enhanced playlist sound or model scoring.

## Result and rubric

**No case was fully faithful: 0/10 in run 1 and 0/10 in run 2 under the rubric below.** This is a strict manual contract audit on ten deliberately challenging prompts, not an estimated failure rate for all users and not a listener quality score. The existing narrow fixture checks passed 2/10 and 3/10 respectively. Six normalized intents were returned in run 1 and seven in run 2; returned intent is not the same as faithful interpretation.

A fully faithful case must return a usable normalized intent and preserve each materially explicit requirement in an appropriate typed field: entity identity/reference role, genre, affect/texture/instrumentation, polarity, degree, count versus time units, restrictions and ordered stages. It must not turn a soft modifier into a universal strict requirement or invent a new restriction. Unsupported requests can pass preservation if their meaning is correctly represented and their unsupported status is explicit; they need not be falsely marked enforced. A correct display note or retained original description alone is insufficient when downstream providers consume incompatible or missing structured fields.

The audit does not demand speculative inferences from use contexts: “for reading” need not invent a BPM, “workout” need not imply aggression, and “rainy evening” need not force a particular musical genre. Exact numeric meanings of “early Aerosmith,” “gentle,” “less aggressive” and “mostly” remain subjective; faithfully retaining those modifiers with appropriate uncertainty is sufficient. The fixture's `instrumental` expectation for “mostly instrumental” is itself too coarse for a future degree-aware contract and should be expanded, rather than blindly imposing no-vocals screening.

## Why the existing passes overstate readiness

`cmd/musiccheck/main.go:462` accepts a genre if its expected text is contained in a genre/style criterion; this does not prove canonical provider compatibility or preserve other modifiers. Cases 1 and 8 pass both runs because their fixture expectations cover only selected fields. Case 4 passes run 2 despite losing era and negative texture. The fixture has no duration target for case 8, no complete polarity/degree assertions and no expectation for “no screaming” in case 10.

The narrow checks are useful incremental regressions, but should not be described as full prompt fidelity. Extend the fixture schema to include expected concepts, source spans, facet kinds, polarity, strength/degree, duration units, reference role, excluded concept/entity, stage scope and unsupported reasons. Assert the absence of spurious mandatory genres or artist exclusions as well as presence of expected values. Keep these checks distinct from API availability, native model health, candidate count and human musical relevance.

## Downstream consequences for Enhanced Hybrid

- **Wrong facets prevent correct classifiers from being consulted.** `internal/reco/multichannel/acoustic.go:55` maps moods only when `Kind == "mood"`; `genre=aggressive` cannot use `mood_aggressive`. CLAP also templates genre versus mood differently (`internal/audio/query.go:18`), so these are material translation errors rather than cosmetic JSON labels.
- **Original text does not repair lost constraints automatically.** `internal/audio/session.go:121` builds clauses from structured fields. Full-prompt fallback is used only when no structured clauses or references exist. This means case 10's missing screaming restriction cannot be assumed to survive just because the original prompt was retained.
- **Late DSP rescue misses observed language.** `internal/reco/multichannel/enhanced_phrases.go:11` and `enhanced.go:51` support a narrow list; `big changes from quiet to loud`, `steady beat` and `warm textures` need explicit reviewed concept translations. “Warm” and “steady” are not single physical measurements and should initially remain soft composite hypotheses.
- **Degree changes admission and count.** `internal/core/vocals.go:6` recognizes exact instrumental/no-vocals intent, not `mostly instrumental`. Correcting that phrase to an unconditional instrumental preference would activate conservative preview screening and could reduce count more than requested. Add degree semantics before broadening the alias.
- **Duration and energy remain contract gaps.** `internal/core/intent.go:166` exposes total track count but no playlist duration target. `internal/reco/multichannel/sequencer.go:130` emits an `energy_trajectory_unsupported` notice instead of enforcing the stored acoustic energy array. Faithful preservation therefore requires explicit unsupported reporting now and actual contract/ranking work before claiming execution support.
- **Schema validation can reject real user intent.** The exclusion prefix pattern at `internal/intent/schema/meaning.go:15` contains no `don't include`/`do not include` form. The error in case 3 run 1 is consistent with that observed validation gap. Expand deterministic negation parsing with exact grounded spans and tests that distinguish a reference from an output restriction.

## Recommended order of remediation

1. Protect counts with units, entity references/exclusions, negative vocal qualities and stage boundaries before invoking the LLM. Correct the `don't include` validator vocabulary without weakening grounding checks. Distinguish local-model failures from bad intent and retain bounded retry diagnostics.
2. Add a shared concept/facet dictionary: genre `classical`, mood `dramatic`, period `20th century`, instrumentation `piano/strings`, mood `aggressive`, vocal quality `screaming`, canonical hard/industrial rock plus modifiers. Preserve arbitrary unsupported words alongside canonical concepts rather than discarding them.
3. Reconcile the LLM result against the protected spans. Explicit exclusions and units override contradictory generated content; soft degree words such as mostly/less/around prevent unwanted hardening. Schema-valid JSON must still pass semantic conservation checks.
4. Compile verified provider plans, then improve evidence acquisition and ranking. Strong matches should lead; user-authorized close matches can fill count with clear optional-facet explanations. Hard exclusions, explicit must/only requirements, deduplication and journey order remain enforced. For case 9, require the actual artists at the first and final positions and include those positions in the total of 15; similarity to the artists is appropriate between those endpoints.
5. Expand these ten fixtures into complete contract checks, then run the parser twice and compare normalized provider plans. Follow with fixed-cache Enhanced replays and controlled preview/listener evaluations. Do not tune fixture assertions merely to reproduce the current bad outputs.

No production code, prompt fixtures or raw reports were changed for this audit. No model/provider request or recommendation was run by this reviewing subtask.
