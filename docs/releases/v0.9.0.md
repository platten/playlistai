# Playlist AI v0.9.0 — Choose your recommendation engine

This minor release adds three recommendation modes, faster exact retrieval,
Windows setup fixes, and an openly reported forty-prompt evaluation across all
three modes. It also includes the local music knowledge and generation-lifecycle
work prepared for the unpublished v0.8.0 draft.

## Your choice of recommendation evidence

Open **Settings → Recommendations** to choose:

- **AcousticBrainz first** (default): supported archived analysis leads overlapping
  characteristics, with CLAP preview comparisons filling gaps.
- **CLAP first**: preview-to-description comparisons lead where available, with
  AcousticBrainz filling gaps.
- **Deej-AI only**: the original audio/co-occurrence embedding walk, without
  metadata discovery, semantic retrieval, CLAP, AcousticBrainz or taste-profile
  ranking. Start with a resolved catalog artist or track.

Priority affects ranking, not permission to bypass hard exclusions. Both evidence
sources can still check eligibility in enhanced modes. Engine-only explains
unsupported strict requirements instead of claiming to verify them. It is not
the same as disabling the local language model, which can still interpret words.

The setting is saved locally and pinned into each new request. Existing results
retain their selected mode through replay and slider changes. Use **Regenerate**
to start again with the current setting. Older requests without a saved mode use
the current desktop default when rebuilt; models, playlists and taste data are
not deleted by switching modes.

## Less repeated work, with exact results

- Request-local, bounded search caches reuse exact similarity results for
  unchanged queries while reapplying current exclusions. Larger searches retain
  an exact fallback; no approximate-neighbor backend was introduced.
- A ten-track reference-generation benchmark fell from **1.888 s to 0.325 s**
  median (about **5.8× faster**) with identical playlists and scoring evidence.
  Allocated bytes fell by about 16%. This isolates recommendation work: startup,
  parsing, provider requests and CLAP inference are excluded.
- Audio progress checks no longer rebuild full evidence snapshots merely to
  inspect cancellation and budget flags. Historical selection helpers now live
  in the test oracle instead of production source.

## Windows setup and native analysis fixes

- Music metadata installation handles Windows SQLite paths correctly, fixing
  the `invalid uri authority: C:%5CUsers...` failure.
- Windows amd64 and arm64 packages build with the native CLAP worker included,
  addressing the “application build has no native CLAP worker” error. The older
  v0.8.0 draft packages predate this correction; install the newly built app.
- Models and compatible inference runtimes still download through setup. Python,
  compilers, bulk metadata dumps and recommendation catalogs are not bundled as
  application runtime prerequisites or release assets.

## Also included for users upgrading from v0.7.0

- Genre/reference discovery with an optional compact local Discogs dataset,
  explicit composer credits, cached provider fallback and archived AcousticBrainz
  evidence. Optional CLAP compares verified preview segments locally; audio is
  discarded while derived features can be reused.
- Generation starts when you press **Generate**, disables the button while busy,
  and opens the returned playlist without a duplicate build. **Regenerate** goes
  back through Generate with the original description.
- Artist-balanced selection, recording deduplication, saved evidence, lossless
  random seeds, and explicit partial/unsupported outcomes.
- A clearer website covering settings, executed benchmarks and known limitations.
  Helper-only Python dependencies were updated without adding Python to the app.

## What the forty-prompt regression actually showed

All **120 cases completed**, each requesting ten songs. The minimum count was
five; full acceptance also checked interpretation, references and artist variety.

| Mode | At least five tracks | All assertions passed |
| --- | ---: | ---: |
| AcousticBrainz first | 39/40 | 38/40 |
| CLAP first | 39/40 | 38/40 |
| Deej-AI only | 9/40 | 9/40 |

Every nonempty playlist contained ten tracks and met its artist-variety rule;
no recording-duplicate or adjacent-artist assertions failed. Each enhanced mode
reported **12 fulfilled, 27 partial and one needs-clarification** outcome.
Track count is not a musical-quality score, and no mode met the minimum for
every example.

Known failures remain documented:

- “Occasional sparkle” was preserved under styles instead of the expected
  texture field.
- The David Bowie → Talking Heads journey returned no tracks: artist names were
  additionally interpreted as essential styles and the chosen destination lacked
  preview evidence.
- Engine-only lacked usable seeds for 26 requests and rejected five unsupported
  requests, including newer destination journeys and strict no-vocals checks.

Median case times were **42.3 s**, **28.3 s** and **0.584 s**, respectively. These
are not controlled speed comparisons: only the first mode parsed fresh, caches
were reused, and engine-only skipped auxiliary work while failing most requests.
The slowest strict instrumental case took **11.8 minutes** in the first run.

Each enhanced run had eligible analyzed-preview evidence for 270 of 390 selected
tracks, but no selected-track AcousticBrainz comparison scores. Some candidate
archive records were available. These results cannot establish a musical-quality
winner between source priorities. No held-out listening judgments or broad CLAP
calibration are claimed; the default LLM was not changed to conceal failures.

## Installation and validation

Packages target Windows and Linux amd64/arm64 and Apple Silicon macOS. Signing
depends on configured release credentials; do not assume every package is signed
or notarized. Users of v0.7.0 must install manually: those binaries do not contain
the newer updater. User data remains outside application replacement targets.

The full local repository gate passed for the included changes: binding
generation, TypeScript checking, production frontend build, Go vet, pure-Go core
compilation, race-enabled tests and zero lint issues. Eight website checks and
rendered checks at five widths also passed. Live acceptance failures above remain
separate from those successful build and deterministic checks.

**Publication checklist:** packaged updater exercises on Windows (NSIS/UAC and
portable), macOS (signed bundle and DMG), and Linux (AppImage and portable) remain
required by the release guide. Cross-compilation does not establish those upgrade
paths. Windows ARM64 native inference, clean Windows runtime prerequisites and
hardened macOS runtime signing also retain documented validation limits.
