# Playlist AI v0.10.0 — Music analysis and recommendation diagnostics

Playlist AI 0.10.0 makes recommendation decisions easier to inspect, introduces
the full-precision music-only CLAP model as the recommended analysis download,
and gives Deej-AI-only users examples that match their selected engine.

These notes describe changes since the published v0.9.0 release. The existing
AcousticBrainz-first, CLAP-first, and Deej-AI-only recommendation modes remain
available. The local language-model default is unchanged.

## See how a playlist was built

Open **Settings → Application logs**, enable **Show detailed recommendation
diagnostics**, then open the log window and generate a playlist. The new option
records the following information when that stage runs and evidence is available:

| Stage | Diagnostic information |
| --- | --- |
| Request | Submitted prompt and available session context |
| Interpretation | Parsed musical intent, parser backend, fallback status, and model completion content/termination reason |
| Provider access | Request URLs with credential-like query parameters redacted, attempts, HTTP status, response size when known, elapsed time, and errors |
| Metadata discovery | Resolved artist pools, track metadata, sources, and discovery notices |
| CLAP analysis | Model identity, preview identity and coverage, per-segment audio embedding vectors, clause scores, eligibility, and analysis totals |
| AcousticBrainz | Available tempo, danceability, loudness, dynamic complexity, key/scale, prediction classes and scores, provenance, and model versions |
| Selection | Each selected track's explanation, retrieval sources, scoring components, generation outcome, and reproducibility information |

CLAP audio vectors are logged when analysis is computed or loaded from cache.
This reuses the record already being assessed; it does not fetch audio again or
add a database lookup solely for logging. AcousticBrainz records contain the
feature projection used by Playlist AI, rather than every field in the upstream
archive. API response summaries and parsed metadata are logged; raw provider
response bodies and request headers are not dumped.

Useful event names include `analysis.clap_audio_embedding`, `analysis.clap`,
`analysis.acousticbrainz_features`, `analysis.acousticbrainz_comparison`, and
`recommendation.pick`.

### Retention and privacy

Detailed collection is **off by default**. Its preference persists across app
restarts, while log records stay in memory. Disabling it removes retained DEBUG
entries and clears them from the viewer when it next refreshes. Ordinary session
logs remain available.

Individual diagnostic records are capped at **64 KiB**, with oversized records
explicitly marked as truncated. The backend retains at most **2,000 records or
16 MiB of log text**. Disabled diagnostics skip payload serialization. This
allows normal CLAP vectors to be inspected while bounding retained log data.

Full prompts, listening context, model output, and track evidence can reveal
private interests. Review excerpts before sharing them. Debug collection does
not write log files or retain preview audio. Derived analysis and saved playlist
evidence continue to use their existing local stores and separate clearing
controls; disabling logs does not erase those stores.

## CLAP Music, full precision

New recommended analysis installations use **LAION larger CLAP Music**, replacing
Music + Speech as the wizard's default checkpoint. The audio and text encoders
are paired FP32 ONNX exports with **512-dimensional embeddings**.

- Encoder downloads total **778,209,534 bytes**, approximately **778 MB**, plus
  tokenizer files and the platform's ONNX Runtime download.
- The bundle declares a **2 GiB memory budget**. This is a configuration value,
  not a newly measured peak-memory guarantee.
- The setup download verifies pinned file sizes, SHA-256 hashes, embedding
  compatibility, and local inference before activating the bundle.
- Users with an older or custom model see a **Recommended update** option under
  **Settings → Music analysis**. Installing the application alone does not
  replace an existing analysis model.
- The existing bundle remains active unless the replacement installs and passes
  its health check. Older analyses remain stored under their original model
  identity; incompatible embedding spaces are never mixed.

Model weights remain separate from the application installers and download only
through analysis setup. The new graphs use the already published, checksummed
model assets hosted under v0.9.0; v0.10.0 does not duplicate those large files.
Desktop execution continues to use compiled Go and the native inference runtime,
without requiring Python, pip, or PyTorch on the listener's machine.

### Executed numerical checks and their limits

The recorded Linux x64 export validation used source revision
`a0b4534a14f58e20944452dff00a22a06ce629d1`:

| Check | Recorded result |
| --- | --- |
| Synthetic audio/text numerical fixtures | 10/10 passed |
| Maximum absolute embedding error | 1.0430813 × 10⁻⁷ |
| Minimum reference/export cosine | 1.0 |
| Tokenizer fixtures | 7/7 exact |
| Preprocessing fixtures | 3/3 within tolerance |
| Maximum preprocessing error | 7.6293945 × 10⁻⁶ |
| Three synthetic audio cases | 143.27–154.32 ms per recorded case |
| Seven text cases | 54.33–66.37 ms per recorded case |

These are recorded export checks, not desktop end-to-end latency or musical
quality benchmarks. A separate four-prompt smoke check found unusually similar
text vectors for unrelated descriptions: cosine **0.998960–0.999329**. The model
therefore retains the existing uncalibrated general-fit policy. Numerical parity
does not establish that it improves recommendations over Music + Speech.

CLAP scores remain preview-scoped similarities, not probabilities. Existing
vocal-screening behavior remains available, but unheard parts of a recording
are unassessed. AcousticBrainz coverage and classifier uncertainty also remain
visible. This release does not add a new held-out listening evaluation or rerun
the previous forty-prompt, three-mode quality study with the replacement model.

## Examples that fit Deej-AI-only mode

The Generate screen now reads the recommendation mode separately from the
parser. Selecting **Deej-AI only** shows exactly these four examples, including
when an LLM is installed:

1. `Bonobo, 10 tracks`
2. `Daft Punk, 20 tracks`
3. `A journey from Justice to Boards of Canada, 15 tracks`
4. `A journey from Radiohead to Sigur Rós, 12 tracks`

The placeholder, guidance, mode badge, and **Surprise me** action follow the same
catalog-reference requirement. Choosing an example fills the description;
generation begins when **Generate playlist** is pressed. Genre and mood examples
remain available in the evidence-aware modes.

These examples guide an artist/reference request or an ordered journey; catalog
resolution and normal eligibility still apply. Their presence does not guarantee
that every requested count can be filled in every catalog or configuration.

## Settings and contributor guidance

The **Off** choice has been removed from **Settings → Track previews**. Deezer
and Spotify remain selectable. Existing saved `off` preferences are not migrated
automatically; select a provider to enable previews if an older installation
still has playback disabled.

For contributors, `AGENTS.md` now defines planning, research, coding, and code
review responsibilities, with file ownership and handoff expectations. The new
`SKILLS.md` covers Conventional Commits, creating and maintaining PRs, a thorough
PR description template, validation, compatibility, and documentation standards.

## Upgrade and packages

Install the package matching your operating system and architecture. Existing
settings, history, catalog data, metadata, and taste profiles remain compatible;
there is no required data reset. Updating the CLAP bundle is a separate action
in Settings. Existing saved playlists retain their evidence; regeneration can
use the newly installed model and its distinct identity.

| Platform | Architectures | Package formats |
| --- | --- | --- |
| Windows | x64, ARM64 | NSIS installer and portable ZIP |
| Linux | x64, ARM64 | AppImage, DEB, RPM, Arch package, and portable TAR.GZ |
| macOS | Apple Silicon | DMG and portable application ZIP |
| winget metadata | Windows x64/ARM64 | `platten.PlaylistAI-0.10.0-winget.zip` |

The release workflow assembles **16 application packages and one winget manifest
ZIP**, validates the application-asset allowlist, and attaches them to the
release. Models, recommendation catalogs, and metadata dumps are downloaded
separately. There is no Intel Mac package. Linux packages use GTK4 and WebKitGTK
6.0; native inference still requires the downloaded platform runtime. Signing
and notarization depend on configured credentials, so OS trust prompts may occur.

## Validation and remaining limitations

The release tree passed the full local `scripts/test.sh` gate: shell checks,
release-asset guard tests, Wails binding generation, frontend typecheck and
production build, Go vet, pure-Go core compilation, race-enabled Go tests, and
golangci-lint with zero issues. Focused tests cover diagnostic opt-in and
clearing, preference persistence, credential redaction, embedding logging,
AcousticBrainz feature payloads, model identity, and compatible installation.

The production `wails3 build` also passed on Linux x64. Its binary reports
`0.10.0` through `--version` and passes the `--check-audio-worker` capability
probe. That probe verifies compiled worker availability, not model inference.

A rendered-browser regression was added for the four Deej-AI examples. Its
latest local execution was blocked by Chromium's missing `libnss3.so` dependency;
the frontend build does not substitute for that browser check. Full native
Windows ARM64 inference, macOS signing/notarization behavior, and every packaged
updater path remain platform-specific validation limits.

Release-commit CI, packaging status, and asset verification are recorded in the
GitHub release description after those checks finish. Earlier forty-prompt and
performance measurements remain historical evidence, not new v0.10.0 results.
