# Playlist AI v0.8.0 — Grounded discovery and local music knowledge

This release improves how a description becomes a playlist, adds downloadable
local Discogs metadata with composer credits, and compares supported intent
characteristics with archived AcousticBrainz analysis. It also fixes regeneration
and strengthens reproducible history, caching, and application updates.

## Better recommendations from descriptions

- Category requests such as “electronic music” are distinguished from explicit
  artist references. Required tracks, inferred retrieval anchors, essential
  criteria, exclusions, and softer preferences remain separate throughout
  generation and replay.
- Genre discovery iterates through real catalog-matched recordings using local
  metadata first, then cached online providers when needed. Optional CLAP preview
  analysis checks supported characteristics before final ranking and sequencing.
  Reaching the requested count alone no longer implies musical fulfillment.
- Selection ranks an overcomplete eligible pool instead of simply returning the
  first acceptable tracks. Personalization, exploration, and diversity cannot
  bypass eligibility checks.
- Genre playlists spread selections across artists and avoid consecutive tracks
  by the same normalized artist. Journey stages and required-track ordering are
  preserved; impossible combinations produce a partial result or clarification.
- Counted requests such as “Classical 10 tracks” retain their requested total.
  Unsupported evidence, limited coverage, or exhausted candidates remain visible
  rather than being hidden by unrelated filler tracks.

## Local music knowledge and composer credits

- The wizard can install an optional compressed Discogs SQLite dataset, separate
  from the application binary. Downloads verify catalog compatibility, declared
  sizes, and SHA-256 hashes before atomic activation.
- The September 2026 composer bundle matches **586,161 of 956,917 catalog tracks**
  (about 61%). It downloads as **92.6 MB** and expands to **312.8 MB**. This is
  metadata coverage, not verified recording-level musical-fit coverage.
- Explicit **Composed By** and **Music By** credits retain source, track positions,
  name variations, and uncertain release scope. Composer identity is not guessed
  from performer names or generic writing credits.
- The new pure-Go `metadatapack` utility downloads checksum-verified dumps,
  imports with bounded multi-core workers, and produces compact runtime bundles.
  Users do not need the multi-gigabyte source dumps or Python.

## Acoustic evidence with honest limits

- Confidently resolved MusicBrainz recordings can receive cached AcousticBrainz
  tempo, key, duration, and supported genre/mood/vocal classifier evidence.
- The `multichannel/v15` engine compares supported positive and negative intent
  clauses against these predictions separately from CLAP similarity. Strong
  opposing or conflicting evidence screens essential requirements; positive
  predictions never bypass existing eligibility rules.
- Expanded playlist details show per-clause comparisons and disagreements.
  Unknown concepts remain unknown. Archived predictions and preview segments
  are not presented as guarantees about an entire recording.
- Preview audio is not retained; derived analysis and evidence snapshots can be
  reused locally. Downloaded AcousticBrainz dump archives are not yet integrated
  into a local runtime index.

## A smoother generation and history flow

- Typing and choosing a sample only edit the description. **Generate** starts
  processing, disables the button, and opens the playlist using the returned
  result without a second build.
- **Regenerate** now returns through Generate with the original description and
  starts a fresh generation once. Cancellation and stale-response protection
  prevent older work from replacing the current result.
- Saved discovery provenance, acoustic evidence, lossless RNG seeds, and profile
  snapshots support reproducible replay. Changed ranking inputs invalidate the
  old candidate sample; unavailable snapshots produce an actionable explanation.

## Fewer provider requests and clearer controls

- MusicBrainz queries share a seven-day cache, including successful empty
  responses. Concurrent identical queries share work; valid stale MusicBrainz
  data can be used during outages without renewing its timestamp.
- Optional token-configured Discogs fallback is capped at **25 requests/minute**.
  Larger result pages and buffered iteration reduce repeated lookups. Discogs
  API responses retain their separate six-hour cache policy.
- **Settings → Music metadata → Clear metadata cache** clears provider caches
  without deleting playlists, taste profiles, installed datasets, or audio
  analysis. Analysis has its own clear control.

## Application updates and installation

Production builds can check for a newer stable release at startup and offer a
verified download and restart. Asset identity, size, digest, architecture, and
archive contents are checked before handoff; unsupported installation locations
get an explanation and release-page link. User data is outside replacement
targets. Install v0.8.0 manually from the assets below when upgrading from an
existing v0.7.0 binary, which does not contain this updater.

Packages target Windows amd64/arm64, Linux amd64/arm64, and Apple Silicon macOS.
The catalog, local metadata, LLM models/runtime, and optional audio-analysis
components remain separate setup downloads. Signing depends on configured
release credentials; do not assume every package is signed or notarized.

## Validation and executed measurements

- The local repository gate passed on the release preparation: generated Wails
  bindings, TypeScript checking, production frontend build, Go vet, pure-Go core
  compilation, race-enabled Go tests, and lint with zero issues.
- The recorded 15-prompt development evaluation produced 90 preview-analyzed
  selections. Live per-case median was **163.8 seconds**; final cached replay
  median was **240 milliseconds**. Live totals combine passing cases and targeted
  rechecks, not one fresh run of this release. All outcomes remained **partial**:
  these execution checks are not held-out listening judgments.
- The composer-aware dump import took **18m 29.65s** with eight workers;
  runtime packing took **1m 17.67s** on the development machine.
- An AcousticBrainz client smoke measured **1.182s cold** and **89 µs cached**
  for one recording. This is a single-sample lookup measurement, not a latency
  distribution or quality benchmark.

The latest Regenerate browser smoke could not run because the local Chromium
environment lacks NSS/NSPR libraries; its script syntax and frontend build/type
checks passed. Packaged updater exercises on Windows (NSIS/UAC and portable),
macOS (signed bundle and DMG), and Linux (AppImage and portable) remain a
publication-checklist item. Automated tests and cross-compilation do not replace
those host-specific upgrade checks.

No new held-out listening-quality result or general CLAP calibration is claimed.
Coverage, model availability, provider access, and identity resolution can limit
results. No default LLM was changed to mask a recommendation failure.
