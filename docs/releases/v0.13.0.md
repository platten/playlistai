# Playlist AI v0.13.0 — Find more music with MERT and offline MusicBrainz

Playlist AI 0.13.0 turns MERT into a working recommendation source, adds a
downloadable offline MusicBrainz index, and gives the prompt parser a much richer
musical vocabulary. Together, these changes help Enhanced Hybrid find fitting
recordings beyond the original Deej-AI catalog while keeping prompts, listening
history, embeddings, and derived audio analysis on your device.

These notes cover all changes since v0.12.1.

## 🎧 MERT now finds similar tracks

MERT moves from being an analysis-only feature into the Enhanced Hybrid
recommendation path.

- **Audio-to-audio retrieval:** a reference track with a cached MERT embedding can
  retrieve compatible tracks from the local embedding cache. Search is bounded,
  recording-deduplicated, deterministic, and version-aware.
- **Works with 30-second previews:** the embedding describes only the analyzed
  preview interval. Playlist AI shows that coverage instead of presenting the
  result as full-track proof.
- **Stable replay:** each generated playlist freezes the MERT search view and
  policy identity. Replaying history does not silently rescan a changed cache.
- **Independent controls:** MERT similarity and deterministic DSP measurements
  have separate switches, caches, status, cleanup, and repair behavior.
- **Graceful sparse coverage:** when too few compatible MERT embeddings are
  available, candidate discovery continues and the Deej-AI model can fill
  remaining slots. Every refill still passes exclusions, identity checks,
  deduplication, ranking, and sequencing.

MERT compares audio with audio. It does **not** understand the text prompt, and a
cosine score is not a probability, beat match, genre label, or promise about an
entire recording.

## 🌍 Discover newer recordings with local MusicBrainz data

Settings and the first-run wizard can now install a compact, searchable
MusicBrainz index from Playlist AI's Cloudflare R2 archive. Candidate and identity
searches use the local index before the public MusicBrainz API, avoiding its
one-request-per-second limit for covered data.

The published v0.13.0 bundle contains MusicBrainz snapshot
`20260912-001001`:

| Download | Size |
| --- | ---: |
| Two Zstandard parts | 283.80 MB |
| Expanded SQLite index | 679.64 MB |

The installer resumes verified parts, enforces HTTPS and size limits, validates
every SHA-256, decompresses with bounded memory, checks the embedded index
manifest and snapshot, and activates the new file only after verification. A
failed update leaves the previous active index in place.

The local index can propose artists and recordings outside the roughly 957,000
tracks in Deej-AI. Playlist AI resolves those candidates to Deezer previews when
available, gathers compatible CLAP, MERT, DSP, and AcousticBrainz evidence, and
then applies the normal ranking rules. Metadata proposes a candidate; it does not
by itself prove that the music sounds right.

## 🗣️ A musical thesaurus that speaks each provider's language

The prompt layer now uses a reviewed, provider-aware thesaurus for genres, moods,
instrumentation, vocals, texture, and listening activities.

- User phrases map separately to descriptive CLAP captions, exact archived
  AcousticBrainz classes, MusicBrainz search spellings, and deterministic DSP
  proxies.
- Ambiguous and numerical language keeps its context. Negation and exclusions
  remain explicit rather than becoming positive similarity hints.
- Unsupported AcousticBrainz or DSP mappings remain unknown instead of being
  invented from a nearby word.
- MusicBrainz discovery aliases broaden search without claiming that every
  returned recording has a verified genre or acoustic property.

MiniLM has been removed from prompt interpretation and model setup. The
deterministic parser, local llama.cpp parser, and optional DistilBERT extractor
remain available. Existing MiniLM-only preferences do not reopen setup or block
startup after upgrading.

## 🧭 Better controls and steadier generation

- MERT setup now lives under **Recommendation models** in Settings and has a
  focused optional step in the wizard.
- Compatible inference workers expose compute-device selection while retaining
  CPU fallback and native health checks.
- Candidate preview analysis runs in parallel within its existing time and item
  budgets, reducing waits when several tracks require evidence.
- Navigating away from Generate no longer discards in-progress playlist state.
  Playlist lengths are clearer, and model/dataset reset controls are grouped at
  the bottom of Settings with confirmation.
- Analysis screens explain long-running work more clearly and retain cancellation
  and retry behavior.
- Surprise prompts no longer inherit an accidental track count from visible UI
  defaults.

## 🎯 Recommendation correctness fixes

- Explicit artist requests stay attached to their intended role during candidate
  discovery and refill.
- Artist exclusions cannot be bypassed by similarity, genre, instrumental, or
  related-artist paths.
- MusicBrainz and Deezer discovery remains request-budgeted, rate-limited, and
  bounded even when candidates fail resolution.
- Required track counts are propagated independently of recommendation search
  internals, preventing lifecycle tests and stale state from changing the target.
- Instrumental searches reuse valid cached evidence and avoid treating incomplete
  metadata as proof of “no vocals.”

## 🛠️ Faster and safer MusicBrainz packaging

Maintainers can build the downloadable index in one command with
`musicbrainzpack`.

- Artist and recording dumps import concurrently through typed, bounded pipelines
  and staged SQLite databases.
- Large JSONL rows stream safely instead of failing at a 16 MiB scanner limit.
- Configurable SQLite caches, long transactions, prepared statements, and artist
  deduplication reduce avoidable disk work.
- Zstandard compression uses a smaller encoder window, computes the index hash in
  the same pass, and splits artifacts below Cloudflare R2's 200 MB target.
- pterm progress bars show download/import throughput, estimated completion, and
  imported row counts. Completed indexes are reused on rerun unless
  `-replace-index` is requested.

The included performance report uses deterministic synthetic fixtures on Windows
amd64. It supports the selected transaction and compression settings, but it is
not a measurement of full-snapshot peak memory or recommendation quality.

## ✨ Updates and maintenance

- The in-app updater now renders Markdown release notes, making headings, lists,
  links, and emphasis readable before an upgrade.
- Windows updates accept an already initialized compatible COM apartment instead
  of failing startup.
- Cross-platform reset paths handle harmless path aliases while still rejecting a
  data directory that is itself a link.
- The Windows race-test script selects the verified LLVM-MinGW compiler and
  restores the caller's environment afterward.
- Linux and macOS CI packaging waits for lint and tests, reducing wasted package
  jobs after an early failure.
- Offline maintainer tooling updates ONNX from 1.18.0 to 1.22.0 and PyTorch from
  2.7.1 to 2.13.0. These Python dependencies are not application prerequisites
  and do not change the distributed ONNX weights by themselves.

## 🔐 Privacy, verification, and licenses

Prompts, listening history, taste data, cached embeddings, and derived audio
features remain local. Explicit online discovery can send extracted artist,
album, recording, or genre searches to MusicBrainz and Deezer; preview audio is
discarded immediately after analysis.

MusicBrainz core data is CC0. Community tags and genres are
CC-BY-NC-SA-3.0. MERT-v1-95M remains optional and licensed
CC-BY-NC-4.0 for noncommercial use. The application remains GPL-3.0-only, and
native/model packs retain their upstream notices.

The release preparation passed the repository's complete Windows gate: 217
frontend tests, production frontend build, `go vet`, race-enabled Go tests, and
lint with zero issues. The merged feature PR also passed CodeQL and native package
builds on Windows, macOS Apple Silicon, Linux amd64, and Linux arm64. These are
software and packaging checks, not a listening study.

## 📦 Installing or upgrading

| Platform | Architectures | Packages |
| --- | --- | --- |
| Windows | x86-64, ARM64 | NSIS installer or portable ZIP |
| Linux | x86-64, ARM64 | AppImage, DEB, RPM, Arch package or portable tar.gz |
| macOS | Apple Silicon | DMG or portable application ZIP |

Existing settings, history, catalog data, analysis caches, and installed models
are retained. MERT remains an optional separate download. The MusicBrainz index
is also optional and downloads only when selected in the wizard or Settings.

Allow temporary disk space for compressed parts and the expanded index during a
MusicBrainz installation. Windows ARM64 is cross-compiled; package build success
does not constitute native ARM64 execution evidence. Signing and notarization
depend on the repository's optional release credentials, so your operating system
may still show its normal warning for an unsigned package.
