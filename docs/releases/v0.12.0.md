# Playlist AI v0.12.0 — Better intent, richer hybrid recommendations

Playlist AI 0.12.0 adds **Enhanced Hybrid recommendations**, strengthens the
translation from your words into musical criteria, and makes updates and setup
more convenient. This release brings together the changes since v0.11.1.

## 🎧 Enhanced Hybrid: more ways to understand the sound

The new optional recommendation mode combines existing catalog, metadata,
AcousticBrainz and CLAP evidence with local audio measurements and optional
MERT audio representations.

- **Describe more than a genre.** Measured preview characteristics can support
  soft sound preferences, while MERT contributes audio similarity and transition
  continuity when compatible analysis is available.
- **Keep musical evidence separate.** CLAP text/audio similarity, MERT audio
  similarity, deterministic measurements and archived classifier predictions
  retain their own identities and coverage. Unknown evidence is shown honestly.
- **Strong matches come first.** Close suggestions carry evidence gaps instead
  of silently claiming every requested trait was verified. Explicit exclusions,
  essential criteria and recording deduplication remain enforced.
- **Reuse analysis.** Derived preview evidence is cached with model and
  preprocessing identities. Temporary preview audio is cleaned up after analysis.

The existing Deej-AI-only, AcousticBrainz-first and CLAP-first modes remain
available. Enhanced Hybrid does not require MERT installation, and an audio
similarity score alone does not prove a genre, mood or full-track characteristic.

## 🧭 Your wording survives the language model

A source-aware English pre-parser now extracts explicit facts before the local
LLM interprets the request. A versioned music dictionary translates recognized
concepts into provider-specific genres, classifiers and CLAP descriptions.

- Better handling of exclusions, indirect negation, compound artist names,
  year alternatives, decades and combined hour/minute durations.
- “Mostly instrumental” retains its preference strength instead of becoming
  an invented universal ban on vocals. Mood and texture are not automatically
  promoted into mandatory genres.
- Explicit source facts constrain the LLM's output. Model-only mandatory
  categories and output roles cannot silently replace the original request.
- Artist journeys preserve actual endpoints: a request moving from Nine Inch
  Nails to Marilyn Manson can keep those artists at the ends, with similar
  eligible tracks between them.
- Ambiguous spelling is confirmed. For a likely “Christian Löffler” typo, choose
  the suggested artist, keep your original wording, or cancel. Keeping the
  original prevents silent fuzzy correction and can leave the name unresolved.

Enhanced Hybrid can also use attributed MusicBrainz, Wikidata and Wikipedia
artist/album context to seed discovery. Lookups are cached, bounded and scoped
to music references; the full prompt and private listening history are not sent
to those services. Artist context guides retrieval and does not certify every
recording's sound.

## ⏱️ Ask for a duration, not just a track count

Duration requests now carry a target, tolerance and known playlist total through
generation, controls and saved history. For example, a **75-minute request with
a one-minute tolerance** targets **4,440–4,560 seconds**, with a variable number
of tracks unless you also specify a count.

Selection preserves required tracks, endpoints and musical constraints while
searching eligible alternatives. Only grounded full-recording duration metadata
can verify the total; a 30-second preview is not treated as a track's length.
Missing durations or an unsuccessful bounded search produce an explanation.

## 🖥️ Native language and audio tooling

The desktop keeps inference in compiled native workers: **Python is not a
desktop prerequisite**. Verified setup paths acquire missing compatible model
and runtime assets. Catalogs and large model weights remain separate downloads,
so application upgrades do not need to redistribute your existing data.

- Native MiniLM support provides an experimental semantic proposal path. It
  remains off by default with conservative acceptance thresholds.
- DistilBERT tooling supports reviewed annotations, training, export and
  calibration. The current small trained pilot remains **inactive**: expanding
  the diagnostic to 128 prompts did not establish useful additional extraction.
- Optional MERT packs have separate model identities and upstream license
  notices. Windows packs include the required app-local runtime dependencies.
- Offline Python preparation and evaluation scripts are documented for people
  building datasets or model packs; they are not needed to run Playlist AI.

## ✨ Clearer updates and less repeated setup

- The startup updater displays **GitHub release notes immediately**, with a
  scrollable “What’s new” section and access to the full release page.
- Existing data and models are checked locally. A healthy completed setup opens
  normally after an upgrade; missing selected capabilities reopen only the
  necessary repair steps.
- Setup skips available assets and rechecks between steps. Newly introduced
  optional features alone do not force everyone through the wizard again.
- Deliberate rules-only parsing and disabled previews are preserved, including
  across restarts. Update progress, cancellation and retry remain accessible in
  narrow windows and both themes.

## 🛠️ Reliability and development improvements

This release preserves full-width random seeds, strengthens update archive
extraction boundaries, and improves cancellation and deterministic cache replay.
CI uses GitHub-hosted runners, parallel validation and reduced fixture/retry
overhead, with timing reports to make further optimization measurable.

## 📊 What the measurements show—and what remains open

On the recorded development comparison with the same 3B language model, the
stricter consumed-intent audit improved from **11/30 to 29/30**. In a bounded
cached 40-playlist replay, returned tracks increased from **270 to 296 out of
495 requested**, and full count requests increased from **16/38 to 18/38**.
Recorded excluded-artist, artist-only and endpoint violations fell to zero.
These gains came from the source compiler and schema changes; MiniLM was disabled
in that comparison.

These are development regressions, **not a representative listening study or
proof that every request now succeeds**. Many replay requests remain partial or
unsupported, and the composer-versus-performer example remains unresolved.
The larger-model comparison and expanded DistilBERT diagnostic are published
with their limitations rather than treated as guaranteed quality improvements.

The final feature tree passed hosted checks for every release build target and
the local Windows gate, including **191 frontend tests**, Go race tests, vet,
lint, bindings, typechecking and production build. Browser fixtures exercised
update and setup states at narrow/wide sizes in both themes. Native installed
updater flows have not been exercised on every platform.

## 📦 Downloads and upgrading

| Platform | Architectures | Packages |
| --- | --- | --- |
| Windows | x86-64, ARM64 | NSIS installer or portable ZIP |
| Linux | x86-64, ARM64 | AppImage, DEB, RPM, Arch package or portable tar.gz |
| macOS | Apple Silicon | DMG or portable application ZIP |

Choose the package matching your OS and processor. Existing settings, history,
catalogs and installed models are retained; no data reset is required. Newly
generated playlists can differ because interpretation and ranking have changed.
Signing depends on the configured release credentials. Windows ARM64 packages
are cross-compiled; a successful build is not native ARM64 execution evidence.
